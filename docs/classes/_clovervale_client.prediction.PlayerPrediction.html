    Class PlayerPrediction

    The player of the page as the page predicts the server will have it, once the server has all its inputs.

    The player moves by the rules of the server, at the rate of the server, from the moment of an input, on the ground of the map it is in. It takes no steps while it rests, and so leaves it to the server to push it out of the way of the villagers who push the players aside then, which shows when a snapshot tells of it, as a correction.

    Each step the page takes is numbered as the step of the server at which the server is to take the same step, and the villager who pushes the players aside is where it is at that step of the server, to stop the player or push it aside. From one step to the next, the numbers go up by one, as the server takes a step of a player that does not rest at every one of its own steps, and each snapshot sets them right. A player that sets off from rest takes its first step at the step of the server that takes its input in: the first step of the server after the input arrives, unless the server has yet to take the steps the input is to come after. The page reckons that step from the steps at which the server took in the inputs it sent before, and from the steps the snapshots tell of, until a snapshot tells it. As long as the inputs take the same time to reach the server, it may be off by as many steps as messages take to the server and back for every input the page sends before it first learns the step at which the server took in an input that did not wait for the steps before it: the first input, or one that came into effect later than the steps it was to come after allowed, the page having learned the step of the input before it as well. After that, it is at most a step off, and right to the step once the server has taken in enough inputs for the page to tell.

    enterMap

    • enterMap(
          map: "village" | "cave",
          progress: InputProgress,
          step: number,
          time: number,
      ): void

      Starts the player afresh in another map, from what the server tells of it there, once the server has told that the player is in that map.

      The player becomes what the server tells, moved on by the inputs the server had not gotten to and by the steps the page has taken that the server had not, as in PlayerPrediction.reconcile, but by the rules and on the ground of that map, as it goes on moving from then on. That is no correction, and the player is drawn there at once, without gliding from where it was. The inputs go on being numbered from where they were.

      Parameters

      • map: "village" | "cave"

        The map the player is in now.

      • progress: InputProgress

        How far the server had gotten with the inputs of the page, and the motion of the player then, in that map.

      • step: number

        The number of steps the server had taken then.

      • time: number

        The time on the clock of the page, in milliseconds, which is no earlier than any time told before.

      Returns void
